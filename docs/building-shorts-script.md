# 지식 쇼츠 대본 제작

## Trigger

쇼츠 소재를 찾거나 대본을 써달라는 요청. 영상 프롬프트만 필요하면 `knowledge-shorts-prompts` 로 바로 간다.

## 속도 예산

| 단계 | 예산 |
|---|---|
| 소재 10개 발굴 | WebSearch 5~8회 |
| 선택 소재 디테일 | WebSearch 3~5회 |
| WebFetch | 전체 2회까지 |
| 총 소요 | 3~5분 |

1. **검증 에이전트를 띄우지 않는다.** 하나가 40~80회 도구 호출로 5~11분을 쓴다
2. **WebSearch 스니펫으로 끝낸다.** 숫자가 보이면 거기서 멈춘다
3. **교차검증을 하지 않는다.** 확인은 마지막 수치 목록으로 넘긴다

## 출력 서식

표는 3열 이하·셀 12자 이내일 때만. 그 외엔 카드형 블록.

## Steps

### 1. 인터뷰 (AskUserQuestion, 3문항)

분야(복수 허용) / 범위(국내·해외·상관없음) / 분량(30·60·90초)

문자 수 × 0.130초. 30초≈230자 / 60초≈460자 / 90초≈690자

### 2. 소재 후보 10개 (검색 5~8회)

검색은 내가 모르는 걸 찾는 데 쓴다. 검색어 예: `<분야> 난공사 일화`, `<국가> 건설 실패 극복`, `2026 <분야> 준공`

**A 서사 4단**: 심각한 문제 → 정공법 불가 → 예상 밖 해결 → 강한 반전
**B 영상 적합성**: ①형태가 한 단어로 그려지나(그물·망·추상은 AI가 못 그림) ②큰 움직임 ③사람·차·배로 크기 재기 ④같은 앵글 before/after ⑤지금도 그 모습

벤치마킹 채널이 이미 다룬 소재는 제외.

카드형으로:

```
### 1 · 스웨덴 키루나 교회 이전 · ★★★★★

> **"113년 된 교회가 도로 위를 굴러갑니다."**

- **문제** — 철광산이 도시 밑을 파먹어 지반이 내려앉는다
- **해결** — 도시를 3km 옮긴다. 교회는 통째로 트레일러에 얹혀
- **반전** — 도시를 무너뜨린 광산 회사가 이사 비용을 낸다
- **영상** — 건물이 도로를 미끄러진다. 바퀴와 군중으로 스케일 완벽
```

10개 뒤 3열 요약표 + 추천 3순위와 이유.

### 3. 디테일 보강 (검색 3~5회)

핵심 수치 2~3개 / **사람 에피소드 하나** / 비교 대상.
사람 에피소드에 검색 한 번을 꼭 쓴다. 재미를 가장 크게 바꾼다.

### 4. 골격 — 100만 조회 대본의 실제 공식

두 계열이 있다. 소재에 맞는 쪽을 고른다.

#### 계열 A · 스토리텔링형 (건축물·역사 구조물)

**1) 오프닝 2단 — 문장 형태까지 고정**

```
여기 [장소]에는 [모순]이 있습니다.
[친숙한 묘사] 지금의 [이름]이죠.
```

> "여기 서울 한복판에는 강인데 흐르지 않는 물이 있습니다. 유람선이 떠 있는 지금의 한강이죠."
> "여기 서울 상암동에 한때 스스로 불을 뿜던 산이 있습니다. 지금은 억새가 뒤덮인 하늘공원이죠."
> "여기 산꼭대기인데 우물이 80개나 있는 성이 있습니다. 경기도 광주 남한산성이죠."

**모순을 먼저, 정체는 두 번째 문장에서.** 순서를 바꾸면 훅이 죽는다.

**2) 세 번째 문장에서 반전 선언**

> "이 물은 저절로 이렇게 된 게 아니라 1986년에 사람이 가둬서 만든 겁니다."
> "그런데 이 산 흙으로 쌓은 게 아닙니다. 쓰레기 9,200만 톤이 그대로 굳은 겁니다."

**3) 첫 문제는 미끼다 — "진짜 문제는"으로 판을 뒤집는다**

문제를 하나 던지고 해결한 뒤, 반드시 이 문장이 온다.

> "진짜 문제는 이 녀석을 치울 방법이 아예 없다는 거였습니다."
> "진짜 문제는 속도였습니다." / "진짜 문제는 따로 있었습니다."
> "그런데 여기서 진짜 문제가 터집니다."

**4) 시청자 대신 질문한다 — 이 스킬의 핵심**

오답 제거는 설명이 아니라 **질문**으로 한다. 시청자가 떠올릴 법한 해법을 대신 말하고 즉시 부순다.

```
그럼 [뻔한 해법]하면 되지 않냐고요?
[그 순간 벌어지는 일]
```

> "그럼 하구를 아예 막아 버리면 되지 않냐고요? 막는 순간 큰물이 졌을 때 불어난 강물이 갈 곳을 잃습니다."
> "그럼 콘크리트로 통째로 덮으면 되지 않냐고요? 쓰레기는 계속 썩으면서 푹푹 꺼집니다."
> "그럼 우물을 깊게 파면 되지 않냐고요? 산꼭대기는 발밑이 통째로 바위라 아무리 파도 물이 안 나옵니다."

**60초 대본에 2~3번 반복한다.** 남한산성은 세 번 쓴다.

**5) 해결이 역효과를 낳는 사슬**

한 번에 풀리지 않는다. 해결 → 역효과 → 오답 → 진짜 해결.

> 한강: 준설 → 물이 더 빠짐 → 하구 막기? → 홍수 → 수중보
> 하늘공원: 흙 덮기 → 메탄가스·불 → 콘크리트? → 침하 → 가둔 채 뽑기
> 경복궁: 담 막기 → 물 갇힘 → 크게 뚫기? → 낙엽에 막힘 → 구역별 천천히

**6) 위기 최고조마다 감정 삽입구**

> "정말 환장할 노릇이죠."

설명 사이에 이 한 줄이 들어가야 사람이 쓴 글이 된다. 대본당 1~2회.

**7) 전환점**

> "그래서 발상을 뒤집습니다."

**8) 종결 — 별칭을 붙인다**

```
[한 줄 별칭] [이름]은 이렇게 탄생한 겁니다.
```

> "산꼭대기의 물그릇 남한산성은 이렇게 탄생한 겁니다."
> "5만 명을 위한 고대 에어컨 벨라리움은 이렇게 탄생한 겁니다."
> "대한민국 최초의 계획도시 여의도는 이렇게 탄생한 겁니다."

이름만 부르면 요약이고, **별칭을 붙이면 새 의미**가 된다.

#### 계열 B · 지식 정보형 (공법·원리·현재진행 공사)

반전이 아니라 **질문 릴레이**다.

**1) 일상 관찰 + 큰 질문**

> "아쿠아리움에 가면 사람보다 몇 배나 큰 거대한 수조를 볼 수 있습니다. 그럼 수천 톤의 물을 담고 있는 이 수조는 대체 어떻게 만드는 걸까요."
> "여기 갈 때마다 항상 공사 중인 곳이 있습니다. 도대체 무슨 공사를 이렇게 오래 하고 있는 걸까요."

**2) 답하고 곧바로 다음 질문**

> "…아크릴의 두께를 결정합니다. 그런데 이렇게 두껍고 거대한 아크릴을 대체 어떻게 하나의 창으로 만드는 걸까요?"
> "…생명 유지 시스템이 설치됩니다. 그런데 몸집이 큰 물고기들은 대체 어떻게 거대한 수조 안으로 옮기는 걸까요?"

답이 끝나는 자리마다 **"그런데 ~는 대체 어떻게 ~할까요?"**를 붙여 다음 구간으로 넘긴다. 3~4번 반복.

**3) 종결**

> "궁금증이 해결됐길 바라며 [대상]은 이렇게 만드는 겁니다."

#### 구간 배치 (60초, 계열 A)

| 구간 | 기능 |
|---|---|
| 0~5초 | 오프닝 2단 (모순 → 정체) |
| 5~8초 | 반전 선언 |
| 8~20초 | 문제 1 + 해결 시도 |
| 20~25초 | 역효과 → "진짜 문제는" |
| 25~35초 | "~하면 되지 않냐고요?" ×2 |
| 35~40초 | "그래서 발상을 뒤집습니다" |
| 40~55초 | 해법 + 수치 |
| 55~60초 | 별칭 + "이렇게 탄생한 겁니다" |

30초로 만들 때는 역효과 사슬을 한 단계로 줄이고 질문을 한 번만 쓴다. 오프닝 2단과 종결 공식은 절대 빼지 않는다.

### 5. 문장 장치

#### ① 모든 수치를 일상 사물로 환산한다

> "9,200만 톤을 옮기려면 25톤 트럭 368만 대분입니다."
> "98m와 96m짜리 쓰레기산 두 개. 아파트 30층 높이입니다."
> "높이 28미터. 아파트 10층입니다."

공법도 같다. 침매공법 = "육상에서 만든 레고 블록을 바다 밑에 가라앉혀 조립", 사일로공법 = "거푸집을 위로 올리며 계속 쌓는 방식".

#### ② 사람을 넣는다

> ❌ 입찰이 유찰됐습니다.
> ✅ 건설사들은 계산기를 두드려보고 전부 손을 들었습니다.

기관명보다 행동으로. "손을 들었다 / 등을 돌렸다 / 매달렸다". 인원수도 사람이다 — "연인원 420만 명이 매달린 공사였습니다".

#### ③ 긴 문장 뒤에 짧은 문장으로 때린다

25~35자 뒤에 **3~8자**. 한 대본에 최소 3번.

> "건설사들은 계산기를 두드려보고 전부 손을 들었습니다. **유찰이었습니다.**"

#### ④ 백과사전체 금지

"~로 알려져 있습니다" / "~인 것입니다" / "또한" / "이러한" / "대표적인" / "중요한 역할을 합니다" / "주목받고 있습니다"

종결은 `-니다` 통일, **현재형**을 쓴다. "쌓았습니다"보다 "쌓습니다".

#### ⑤ 시간 압박을 넣는다

> "장마가 오기 전에 끝내야 했죠." / "단 110일 만에 올라갔습니다." / "47일 동안에도"

#### ⑥ 수치는 물타기 쓰지 않는다

확신이 덜해도 구체적인 숫자를 그대로 쓴다. "약 30미터"나 "수십 미터"로 도망가면 대본이 죽고, 물타기한 숫자 옆에는 비유를 붙일 수도 없다.

> ❌ 수십 미터 깊이의 바다입니다.
> ✅ 수심 30미터입니다. 아파트 10층 높이를 물로 채운 셈입니다.

안전장치는 문장이 아니라 마지막 확인 목록이 맡는다. 다만 아예 모르는 숫자를 지어내지는 않는다.

### 6. 소리 내어 읽기 검사

어디서 손가락을 올리고 싶어지는지 찾는다.
- 새 정보 없는 연결 문장 → 삭제
- 숫자만 있고 비유 없는 문장 → 비유 추가
- 같은 길이 세 문장 연속 → 하나를 짧게

### 7. 산출물

1. 나레이션 전문 (코드블록)
2. TTS 붙여쓰기 버전 + 무음 위치
3. 문자 수와 초 환산
4. 확인 권장 수치 목록 — 검색으로 본 건 ✓, 못 찾은 건 ⚠️. "업로드 전 확인하시거나, 팩트체크를 따로 요청하세요"
5. 출처 링크 — 검색으로 본 것만

마지막에 `knowledge-shorts-prompts` 로 이어갈지 물어본다.

## 자가 체크리스트

- [ ] 오프닝이 "여기 [장소]에는 [모순]이 있습니다" + 정체 공개 2단인가
- [ ] **"~하면 되지 않냐고요?"가 2회 이상 있는가**
- [ ] **"진짜 문제는~"으로 판을 한 번 뒤집었는가**
- [ ] 해결이 역효과를 낳는 사슬이 있는가
- [ ] "정말 환장할 노릇이죠"가 위기 최고조에 있는가
- [ ] "그래서 발상을 뒤집습니다"가 전환점에 있는가
- [ ] **종결이 별칭 + "이렇게 탄생한 겁니다"인가**
- [ ] 모든 수치 옆에 일상 비유가 붙었는가
- [ ] 물타기 수치 표현이 하나도 없는가
- [ ] 사람이 등장하는가
- [ ] 짧은 문장(3~8자)이 3번 이상인가
- [ ] 백과사전체 표현이 하나도 없는가
- [ ] 문자 수 × 0.130 ≈ 목표 초수인가

## Verification

- 검증 에이전트를 띄우지 않았는가
- 검색 총 13회 이내, WebFetch 2회 이내인가
- 전체 5분 안에 끝났는가
- 계열 A와 B 중 소재에 맞는 쪽을 골랐는가
- 오프닝 공식과 종결 공식을 글자 그대로 적용했는가
- "~하면 되지 않냐고요?" 질문이 실제로 들어갔는가
